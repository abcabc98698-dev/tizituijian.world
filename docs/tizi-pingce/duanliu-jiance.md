## 一、网络断流的三大常见病灶排查模型

```
[ 网络断流逐层排查技术架构图 ]

[ 本地电脑 ] ──(第 1 段)──> [ 家用路由器 Wi-Fi ]
    │
    ▼ 检查: ping 192.168.1.1。若丢包 > 0%，说明本地无线信道干扰，切换 5GHz 网线
    │
[ 本地网络 ] ──(第 2 段)──> [ 机场境内 BGP 入口 ]
    │
    ▼ 检查: mtr --tcp -P 443 入口IP。若在省骨干网丢包，说明国内跨网调度异常
    │
[ 跨境专线 ] ──(第 3 段)──> [ 境外落地机房 ]
    │
    ▼ 检查: 专线物理二层隔离。若丢包，说明商家物理光纤中断或超售挤爆！
```

## 四、自动化 MTR 诊断脚本实战

在 Linux 或 macOS 终端运行以下单行命令，对目标代理节点持续监控 100 次跳数：

```bash
# 持续 100 次发包并生成详细报告
mtr -n -c 100 --report-wide 目标入口IP
```

**排障判别准则**：
- 如果丢包发生在第 1 跳（192.168.1.1）：属于本地家庭 Wi-Fi 路由器问题；
- 如果丢包发生在第 2~4 跳（本地省内电信骨干）：属于本地宽带光猫或运营商本地故障；
- 如果丢包发生在最后几跳（境外目标）：属于服务商落地机房超售断流。

## 五、断流排查常见问题解答 (FAQ)

### Q1：为什么有时候看网页正常，但 Telegram 总是频繁提示「Connecting」？
因为 Telegram 使用的是 MTProto 协议持续长连接，对 TCP 连接的保持极其敏感。很多劣质机场的公网中转服务器为了节省内存资源，将 TCP 连接的超时销毁时间（Timeout）设定得很短（如 30 秒无数据即强制掐断），导致 Telegram 频繁重连。优质专线梯子会保持长达数小时的长连接活跃态。

### Q2：开启 TUN 模式有助于减少断流吗？
有帮助！TUN 模式通过虚拟网卡在操作系统最底层接管数据流，避开了传统系统代理注册表被第三方杀毒软件频繁篡改的风险，能够有效提升网络连接的持久稳固性。

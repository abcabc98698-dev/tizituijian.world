## 四、如何用路由追踪（NextTrace）鉴别假专线

许多不良商家用公网普通中转冒充「IEPL 专线」。通过以下诊断命令可一眼看穿真伪：

```bash
# 使用 NextTrace 检测专线路由
nexttrace --tcp 目标节点IP
```

**真伪专线判别法则**：
1. **真 IEPL/IPLC 专线**：从境内机房（如深圳/上海 BGP）出发后，下一跳**直接进入境外局域网私有 IP（如 10.*.*.* 或 100.64.*.*）或直接落地香港 HKIX 交换中心**，中间绝对不经过公网 202.97（163骨干网）或 59.43（CN2 骨干网）；
2. **假冒专线（公网中转伪装）**：在境内机房与境外机房之间，出现了连续多跳公网路由，甚至在跨越公网时出现高丢包。

## 五、线路架构常见问题解答 (FAQ)

### Q1：IEPL 和 IPLC 到底哪一个更好？
两者在用户实际体验上均属于**晚高峰 0 丢包的顶级第一梯队**。严格从通信工程角度看，IPLC 是物理层（Layer 1）时分复用硬切片，抖动更极限；IEPL 是数据链路层（Layer 2）以太网封装，带宽调度更灵活、性价比更高。对绝大部分用户而言，两者的稳定性和速度几乎没有可感知的差别。

### Q2：为什么有些专线节点 Ping 值显示 10ms，但打开网页却很慢？
因为你在客户端测速时，Ping 测到的仅仅是**你本地到境内入口 BGP 机房的延迟**（入口延迟）；而网页加载速度取决于「入口 → 专线跨境传输 → 境外落地机房 → 目标网站服务器」的**端到端真实 RTT 延迟**。如果落地机房带宽超售严重，就算入口 Ping 只有 1ms，网页依然会转圈。
